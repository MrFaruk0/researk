# Support

## Current status

Researk is pre-alpha and currently has no runnable or supported release. The repository is open for architecture, specification, documentation, and project-foundation work. Installation and runtime support will begin only after executable artifacts are published.

Support is provided by the community on a best-effort basis. There is no service-level agreement, guaranteed response time, hosted service, or private customer-support channel.

## Where to ask

- Use [GitHub Issues](https://github.com/MrFaruk0/researk/issues) for reproducible bugs and scoped work items.
- Use [GitHub Discussions](https://github.com/MrFaruk0/researk/discussions) for questions, setup help, workflow ideas, and open-ended design conversation.
- Use the repository's [security policy](SECURITY.md) for suspected vulnerabilities. Do not disclose vulnerabilities in a public issue or discussion.

If Discussions are not yet enabled, use an issue and clearly mark it as a question. Maintainers may move or close requests that belong in another channel.

## Before opening a request

Search existing issues and discussions, then collect the smallest example that demonstrates the problem.

For implementation problems, include when applicable:

- Researk version or commit,
- installation method,
- operating system and architecture,
- terminal and shell,
- provider and model names without credentials,
- redacted configuration relevant to the problem,
- exact reproduction steps,
- expected and actual behavior,
- minimal logs or error output.

Do not upload API keys, tokens, credentials, private manuscripts, unpublished results, participant data, proprietary datasets, or other sensitive research material. Replace them with a minimal synthetic example.

## Support boundaries

Project support covers Researk's software, documentation, packaging, and documented integrations. It does not guarantee support for every model, provider outage, third-party API, terminal, journal workflow, or local environment.

Researk can assist research workflows, but project support is not scientific peer review, statistical validation, medical or legal advice, or a guarantee that generated material is accurate or publication-ready. Researchers remain responsible for verifying papers, citations, analyses, reproduced results, and submission requirements.

## Supported versions

Until the first release, only the current repository state is relevant and no compatibility promise is made. Once releases exist, this section will define the supported release window and security-fix policy.
